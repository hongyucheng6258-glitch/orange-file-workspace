# 应用设置中心设计规格

## 1. 目标与范围

本次将现有“应用信息 + 备份恢复”页面完善为可管理应用行为的设置中心。应用主侧边栏保持不变，设置页面内部采用顶部标签导航。

首期覆盖通用、外观、存储、忽略规则、备份与恢复、关于六个分类。普通设置分项即时保存；目录迁移、备份恢复和删除等高风险操作必须单独确认。

本次不包含账号、云同步、多人配置同步、插件设置和复杂计划任务表达式。

## 2. 页面结构

顶部标签依次为：通用、外观、存储、忽略规则、备份与恢复、关于。宽窗口显示完整标签，窄窗口允许横向滚动，不增加第二层侧边栏。

| 分类 | 设置内容 |
|---|---|
| 通用 | 启动行为、默认导入模式、重复文件策略、预览大小上限 |
| 外观 | 跟随系统、浅色、深色、界面紧凑度 |
| 存储 | 数据目录、托管目录、空间占用、自动迁移 |
| 忽略规则 | 内置规则、自定义文件名和路径规则、启用状态 |
| 备份与恢复 | 手动备份、自动备份、保留数量、导出、删除、恢复 |
| 关于 | 应用版本、数据库版本、运行环境和路径信息 |

页面统一展示加载、保存中、保存成功、失败、禁用和后台任务状态。错误信息使用独立的错误样式，不与成功提示共用视觉语义。

## 3. 设置数据

现有 SQLite `app_settings` 表是普通设置的唯一来源。前后端共享明确的 `AppSettings` 数据结构，前端不得传入任意键名，后端负责默认值、类型校验和范围限制。

建议设置项包括：

- `general.launch_behavior`
- `general.default_import_mode`
- `general.duplicate_policy`
- `general.preview_size_limit_mb`
- `appearance.theme_mode`
- `appearance.density`
- `storage.managed_dir`
- `ignore.custom_rules`
- `backup.enabled`
- `backup.frequency`
- `backup.run_time`
- `backup.retention_count`
- `backup.backup_type`

数据目录属于应用启动配置，不能只写入当前数据库。修改时由目录迁移流程原子更新启动配置，重启后再次验证。

## 4. 保存机制

普通设置修改后先更新界面并显示保存状态，后端校验通过后持久化。保存失败时恢复原值并显示具体原因，避免前端状态与实际配置不一致。

主题修改立即生效；“跟随系统”模式监听系统主题变化。导入策略、预览限制和忽略规则从下一次相关操作开始生效。每个分类提供恢复默认值操作，并在执行前显示影响范围。

## 5. 目录自动迁移

目录调整只提供自动迁移，不提供仅修改路径。完整流程如下：

1. 选择目标目录并检查路径合法性、写入权限、目录冲突和可用空间。
2. 暂停导入、预览生成、文件监控及其他会写入旧目录的任务。
3. 将内容复制到目标位置的临时目录，并持续上报阶段、进度和当前文件。
4. 校验文件数量、总大小、数据库和关键文件；必要时抽样或完整校验摘要。
5. 原子切换启动配置和托管目录配置，重新打开数据库并恢复相关服务。
6. 验证新目录可正常读写后再清理旧目录。
7. 任一步骤失败时恢复旧配置，保留旧目录并清理不完整的临时目录。

配置切换前允许取消；进入原子切换阶段后不可取消。应用异常退出后，下次启动根据迁移状态记录完成清理或回滚。

## 6. 备份与恢复

支持手动元数据备份、手动完整备份，以及每天或每周自动备份。自动备份可配置执行时间、备份类型和保留数量；错过计划时间时在下一次启动补执行一次，同一周期只执行一次。

每份备份记录应用版本、数据库版本、备份类型、文件清单、文件大小和校验摘要。超出保留数量后清理最旧的自动备份，不自动删除手动备份和恢复前保护备份。

恢复前必须检查备份完整性、版本兼容性、可用空间和关键文件，并自动创建保护备份。恢复先落到临时目录，校验成功后再切换；失败时自动回滚。备份列表支持删除、导出、打开所在位置和查看失败原因。

## 7. 后端边界

后端提供以下受控能力：获取完整设置及默认值、更新单项设置、恢复分类默认值、校验迁移条件、启动和取消迁移、查询迁移进度、查询存储占用、创建和管理备份、恢复备份、更新自动备份计划。

目录迁移、完整备份和恢复统一接入任务中心，通过事件上报状态，避免同步调用阻塞设置页面。设置、导入、预览、监听和备份服务必须从统一配置来源读取值。

## 8. 异常处理

普通设置失败时恢复原值；输入无效时阻止保存并就地说明；后台任务失败时保留原数据，在任务中心记录失败阶段和重试入口；高风险操作失败时自动回滚并说明当前有效数据位置。

迁移和恢复使用结构化任务日志。界面只展示可理解的信息，日志保留内部错误链和阶段信息，便于诊断。

## 9. 测试策略

前端覆盖标签切换、即时保存、失败回退、表单校验、确认对话框及窄窗口标签滚动。Rust 单元测试覆盖默认值、类型和范围校验、路径检查、备份保留规则及周期判断。

集成和故障测试覆盖设置持久化、主题恢复、自动备份、备份完整性、空间不足、无写入权限、复制中断、数据库重开失败、主动取消和启动后回滚。回归测试确认导入、预览、文件监听和备份均使用新配置。

## 10. 验收标准

1. 普通设置即时保存，重启应用后保持一致。
2. 主题立即生效，并能响应系统主题变化。
3. 保存失败时界面恢复原值且错误原因清晰。
4. 数据目录和托管目录可安全迁移，失败后旧数据仍可使用。
5. 自动备份按每天或每周执行，并正确限制保留数量。
6. 损坏或不兼容备份不能进入正式恢复阶段。
7. 恢复失败后可回到恢复前状态。
8. 长任务不阻塞设置页面，并可在任务中心查看进度。
9. 窄窗口无内容重叠，顶部标签可横向滚动。
10. 应用主侧边栏及其他功能导航不受影响。

## 11. 实施顺序

建议按设置基础设施、外观与通用设置、忽略规则、备份管理、自动备份、目录迁移的顺序实施。目录迁移风险最高，放在统一配置、任务状态和备份保护机制稳定后开发。
